# Contributor instructions

Read README.md, SECURITY.md and docs/ARCHITECTURE.md before changes. Preserve downloader authentication, per-torrent identity, cumulative accounting, credential encryption and durable recovery ownership contracts.

Never operate on a real downloader in tests. Use isolated httptest/Playwright fixtures. Do not commit actual credentials, passkeys, data volumes, SQLite files, encryption keys, private screenshots or logs.

The latest product contract is per-downloader strategy start/stop, default on for configured downloaders; monitoring remains active independently. A stop explicitly clears that downloader's torrent-level limits, including unowned limits, and persists failed work for retry. Global downloader limits remain untouched. Do not reintroduce per-torrent or downloader AutoManage opt-in controls. The default main+independent guardian deployment remains required; whole-host/guardian outages cannot recover remotely. Persist intents before writes and verify readback; external manual changes still suspend ownership until an explicit restart of that downloader strategy.

Frontend now follows the user's Uptime Kuma reference for green/gray theme tokens and Font Awesome solid icons, keeping compact device layouts, system/dark/light theme and Chinese/English preferences. Do not copy the Kuma mascot or claim affiliation. Main content must remain centered in the usable area beside the sidebar on 4K displays. Creation must work over ordinary NAS HTTP, not just localhost/HTTPS. Browser verification requires screenshots at desktop/tablet/mobile and interaction checks; a build is not visual QA. Keep all test fixtures and operational helpers outside the public repository unless they are self-contained synthetic unit/integration tests.

Run frontend production build, Go tests/vet, Linux race tests and isolated fault injection before publishing. Retain pinned dependency locks, cross-architecture Docker builds and versioned tags. Do not push to another existing project's Docker repository.

Tracker discovery persists hostname-only automatic rules, preserving renamed IDs and existing weights. New site weight is 10 (range 1–10), default fixed minimum is 50,000 B/s per active torrent. Weighted site shares split equally inside the site; redistribute only when fixed floors require it. Floors take precedence over both budget and site cap, with explicit warnings, never silently reduced. Missing metadata uses a truthful Tracker-unavailable group, not fabricated site attribution. Lists use API pagination (50), preserve full site-rate aggregates and must show active failures as well as successful allocations.

Webhook layout/template behavior and portablebackup validation are adapted from the existing Gallery/Movie projects; retain documented provenance. Draft tests must not save or enable configuration. Headers remain encrypted/redacted. Reports and alert jobs are persisted, bounded retries (1/5/15m, max4) and explicit duplicate-delivery limits. Backup imports validate before a transaction, preserve rollback archives, reencrypt imported credentials with the current key, revoke sessions and leave every imported downloader strategy paused. Do not replace an open SQLite file shared with guardian. Backups are private; never commit fixtures or archives.

Charts use actual per-site samples, never fabricated splits of legacy totals. Support5/15/30m,1/3/6/12/24h, retaining gaps for missing data. Stack absolute per-site traffic and show shares in tooltips; do not normalize all bars to100%. Keep menu labels four Chinese characters, Webhook/backup above settings, About policy text accurate, single language toggle, compact resizable columns with upload speed distinct from allowance, and no duplicate torrent control list on outlet pages. Preserve0.1.5 backup compatibility for the new optional history table.
