# 总上传 1M 的配置示例

这里的 **1M 按下载器常用的 1 MiB/s** 计算，即 1,048,576 字节/秒，约 8.39 Mbps。若你说的是运营商 **1 Mbps 上行**，预算应填约 **0.119 MiB/s**，不能填 1。

## 先接入和分组

1. 下载器 → 添加 qBittorrent / Transmission，先测试再保存。TR 可以填 `http://NAS地址:9091` 或完整 `/transmission/rpc`；常见 Web 地址也会转换成 RPC 地址。
2. 站点统计 → 创建站点 A、B，填写各自 Tracker 域名；同一站点的多个域名放在同一个配置中。
3. 带宽策略 → 添加带宽池，名称“家庭上行”，**总上传额度填 1 MiB/s**，暂不开启。
4. 编辑同一家庭出口下的 qB、TR，所属带宽池都选“家庭上行”。不同公网出口不放到这个池。

## 两个站点的参数

| 设置 | 站点 A（优先） | 站点 B |
|---|---:|---:|
| 优先权重 | 3 | 1 |
| 最低额度 MiB/s | 0.10 | 0.10 |
| 最高额度 MiB/s | 0（不额外封顶） | 0（不额外封顶） |
| 日目标 / 月目标 GiB | 0（关闭） | 0（关闭） |
| 达标后额度 MiB/s | 0.05 | 0.05 |

日/月目标关闭时，“达标后额度”不会参与分配。最低额度之和不能超过池总额度。

两个站点都存在活跃种子时：先各分 0.10，剩余 0.80 按 3:1 分配，最终约为 **A=0.70 MiB/s、B=0.30 MiB/s**。受下载器限速单位影响，会向下取整到可用精度。

只有 A 有上传连接时，A 可获得约 1 MiB/s。A 中两个同权重种子会平分 A 的站点额度。没有上传连接的种子经过释放延迟后恢复为种子级不限速；下载器原有全局限速不会被改动。

## 开启与查看

1. 点击需要管理的种子，指定唯一站点归属，种子内权重填 1，开启“允许系统接管此种子上传限速”。没有开启的种子不会受本系统预算控制。
2. 使用默认主程序＋独立守护部署，确认“恢复保护在线”，再启用“家庭上行”带宽池。
3. 等待一个采样周期（默认 5 秒），在页面和下载器两边查看种子限速。实际上传速度取决于其他 peer 是否下载，不保证跑满配置值。
4. 默认无连接释放延迟 15 秒，防止连接抖动；需要停止时点“恢复系统限速”，会关闭调度并解除本系统接管的限速。

## 1M 是调度预算，不是网络层硬封顶

本工具通过轮询设置各个种子的限速，存在采样和 API 延迟；未接管种子也不受此池约束。要保证整条出口在任何瞬间都不超过 1 MiB/s，应在路由器/主机做统一上传限速或 QoS。

不要把 qB、TR 的全局限速都设为 1 MiB/s 后认为合计仍是 1：两者可能合计达到 2。分别设固定全局上限虽然可以限制合计，但会削弱另一个下载器空闲时动态借用额度的能力。选择统一出口 QoS 更适合同时保留动态分配。

主容器正常退出会尝试恢复，异常停止由独立守护在心跳过期后处理。若独立守护、下载器或整台主机也不可达，需等恢复连接后再解除，无法凭空远程修改限速。
