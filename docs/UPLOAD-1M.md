# 共享出口 1M 的配置

为便于核对，本例按十进制 **1,000 KB/s = 1,000,000 B/s** 计算；如果是 **1 MiB/s**，则为1,048,576 B/s。**1 Mbps** 只有125,000 B/s，三者不同。

## 配置

1. 创建一个出口，上传带宽填 `8 Mbps`，即1,000,000 B/s。默认50 Mbps出口也可直接修改。若需要1 MiB/s，则填8.388608 Mbps。
2. QB与TR选择同一个出口；不是给每个下载器各分1M。不同真实出口可以分别配置，预算互相独立。
3. 站点A/B/C权重设1/2/2，每个活跃种子最低额度保留50 KB/s；站点最高额度、日/月目标先保持0。
4. 每个下载器的自动策略默认启动，统计一直运行。可在下载器列表独立停止和启动，不需要逐种子勾选。

## 结果

| 活跃情况 | 额度 KB/s |
|---|---|
| 只有A一个种子 | A=1,000 |
| A/B各一个、权重1:1 | 各500 |
| A/B/C权重1:2:2，种子数1/1/2 | A=200，B=400，C两个各200 |
| 十站权重相同、每站两个 | 每站100，每种子50 |
| A/B权重相同，种子数1/19 | A=50，B总计950，B每种子50 |
| 总计25个种子、最低50 | 合计1,250，明确提示超过1,000预算，最低额度不降低 |

先按站点权重分总预算，只有最低额度不足时重新分配。**不先扣掉所有最低额度再按权重分剩余**，以免正常情况下的站点比例偏离设置。下载器API按整数速率取整，额度可能有微小差异。

## 停止与边界

停止某个下载器策略会清空它全部种子级上传限速，保留全局限速；另一个下载器继续运行，并重新分配可用额度。闲置释放默认延迟15秒，需同时无上传连接和无上传流量，避免连接统计漏报。

最低额度优先于出口预算，链路仍可能无法兑现所有额度；本工具无法凭空增加物理带宽。下载器全局限速、peer需求、轮询延迟都会影响实际速度。需要网络层绝对上限请在路由/主机侧配置，但那也会使实际速度无法保证固定最低额度。

默认主服务+独立guardian可处理主服务掉线后的系统限速恢复；守护、下载器或主机也不可达时需要等待恢复连接。运行记录和Webhook告警可查看异常与重试。
