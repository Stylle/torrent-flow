# Architecture

One Go executable serves an embedded React/Chart.js frontend, a sampling controller and a default embedded recovery worker. The default Docker deployment now uses an independent guardian with EXTERNAL_GUARDIAN=true, prioritizing recovery while the main container is stopped. The same executable with `--guardian` runs an independent recovery process/container. Both use one private data volume and SQLite WAL with durable transactions; no Redis or third-party hosted backend is needed.

`Client` adapters authenticate against qBittorrent WebUI v2 and the legacy Transmission RPC protocol (still supported by Transmission 4). Transmission's newer protocol is not required; future versions removing legacy RPC need a new adapter. RPC 409 session negotiation and per-client upload units are tested. TR RPC accepts bounded same-origin redirects preserving POST and session negotiation; cross-origin credential redirects remain refused. Common Web/base URLs are normalized before validation. Tracker URL lists are cached for two minutes; raw URLs remain in memory for matching and are never sent to browsers. Peer interest/connected-leech counts approximate upload demand; they are not per-tracker transport attribution.

The encrypted settings blob contains all client secrets and rules. A separate master key file is generated per installation. Cumulative torrent counter deltas are added transactionally into hourly accounting rows; speed history remains separate. Original counter baselines, period boundaries and retention are covered by tests. A gap or cross-midnight counter interval is flagged as temporally uncertain, not invented as exact per-minute traffic. Rules affect new deltas, preserving old attribution.

The allocator first distributes each outlet's total budget by active site weights (1–10), then splits the site share equally across its active torrents on all bound downloaders. It adjusts shares only to meet fixed per-torrent floors. The default floor is 50,000 bytes/sec; floors take precedence over outlet budgets and site caps, with warnings when infeasible. They are never reduced or released merely because the budget is smaller. Global downloader settings remain unchanged. Each downloader independently starts/stops its strategy; monitoring always runs. Explicit stop durably queues clearing all torrent-level upload limits on that downloader, including unowned limits. Old AutoManage/Manage flags remain for JSON compatibility but do not gate allocation.

Limit ownership records contain original, last-observed, planned and confirmed state. The intent transaction commits before the outbound command. A second write transaction serializes command/readback with the guardian, verifies the intent still exists and checks the heartbeat before sending. Recovery accepts either last or planned value for an interrupted owned command. A first command never sent preserves the user's prior setting. A value differing from both is an external change, retained and recorded as a persistent control block.

The recovery worker recovers stale-controller ownership after thirty seconds. Embedded recovery cannot survive the whole process/container being stopped; Docker restart invokes startup reconciliation. The default independent Docker worker survives controller-container shutdown. It does not depend on the controller's web server or a raw copied database. The entire host, guardian or downloader being unavailable prevents immediate remote recovery; pending entries remain for retry. Both processes require a local filesystem supporting SQLite WAL/locking; use a local Docker volume or local bind mount, not an unreliable network share. A single active controller and one guardian per data directory are supported.

Controller network work is serialized against configuration mutations; a separate runtime-state mutex allows the dashboard to read the last complete snapshot without waiting for a full tracker enumeration. Configuration uses revisions to reject stale saves. Updating destinations, credentials, budgets or ownership first restores old managed limits using the old credentials. Refusal to restore is a visible error; users cannot silently delete the only credentials needed for recovery.

If an administrator changes recovery connection credentials/address because the old endpoint is no longer reachable, the replacement must read every outstanding owned hash and a consistent recorded limit before it is accepted. The repaired connection is persisted before recovery, control is temporarily disabled, and unresolved records remain on failure. Pending recovery on one unreachable downloader must not prevent monitoring other configured instances.

Sessions are opaque random tokens stored as hashes, with independent CSRF tokens, same-origin validation and SameSite/HttpOnly cookies. Login attempts are bounded. A password change revokes all old sessions. Admin-selected LAN destinations are intentional and are not an untrusted public URL fetch endpoint.

Traffic deltas for a torrent/site/hour are accumulated into an existing row within the same baseline transaction. Existing historical rows are preserved. Different uncertainty states remain separately identifiable. Speed history is sampled at most once per fifteen seconds and expiry cleanup is throttled to once per hour.

Tracker discovery runs inside the controller configuration lock before ingestion, preserving renamed sites and manual rules. New sites default to weight10 and a 50KB/s per-torrent minimum. Tracker-less/temporarily unavailable metadata uses a named fallback; existing historical attribution is not rewritten. Overview includes active pending/failed torrents, not only successfully managed ones. API pagination limits rendered/transferred torrents to50 while site speed aggregates use the full set. qB supplemental tracker queries are bounded per poll and cached; observed unchanged limits avoid redundant reads/writes.

Webhook configuration lives in the encrypted configuration blob; secret headers are redacted and blank-preserved. Template escaping is adapted from Wusaqi Gallery. A single controller worker persists due-period/alert IDs and immutable payloads in notification_jobs, retries at1/5/15m up to4 attempts, suppresses acknowledged repeats, and expires work after24h. Lost responses can still cause duplicates; Idempotency-Key is provided. Tests use current drafts without saving. Background notification dispatch and backup import serialize through notifyMu.

Full ZIP snapshots/validation reuse internal/portablebackup from today-random-movie-web. Import validates checksums, app identity, SQLite integrity, account and decryption before copying allowlisted data in one transaction. Existing master.key remains stable for the independent guardian, imported settings are reencrypted, sessions and old leases are not replayed, and all imported strategies are paused. A pre-restore archive is retained. This avoids replacing a database/key pair opened by a second process.
